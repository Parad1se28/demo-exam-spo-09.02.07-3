# demo-exam-spo-09.02.07-3
💻 Демонстрационный экзамен 2026

Информационные системы и программирование (09.02.07)
Специализация: Разработчик веб и мультимедийных приложений

📌 О проекте
Данный репозиторий посвящён полной реализации демонстрационного экзамена 2026 года по разработке информационных систем (веб-портал заявок на курсы).
Проект построен на принципе «максимум баллов при минимуме сложных технологий». Идеально подходит для сдачи экзамена в условиях полного отсутствия интернета, npm-пакетов и современных фреймворков.

Проект включает:

Готовый бэкенд на Django (только API, никакой лишней логики).

Чистый фронтенд (Vanilla JS, HTML, CSS), который запускается вообще без сборщиков.

Готовые SQL-скрипты для быстрого развертывания базы данных.

Советы работы на экзамене с офлайн-документацией.

📎 Для успешной сдачи не нужно зубрить сложные алгоритмы, достаточно понимать поток данных (Data Flow) и использовать самые надежные инструменты.

🎯 Цель
Помочь студентам подготовиться к демоэкзамену, предоставив пуленепробиваемый шаблон приложения, который можно написать руками за пару часов, опираясь только на скачанный DevDocs.

🧰 Используемый стек и технологии
Мы намеренно отказались от Vue.js, React и TailwindCSS. Причина проста: на экзаменационном ПК без интернета они превратятся в тыкву.

Backend: Python + Django (минималистичная настройка views.py и urls.py).

Frontend: HTML5, CSS3, Vanilla JavaScript (Fetch API).

База данных: PostgreSQL.

Среда разработки: Visual Studio Code (Live Server) + DBeaver / pgAdmin.

💡 Лайфхаки и самые быстрые решения
В этом проекте собраны "читы" для экономии времени на экзамене:

Проектирование БД и ER-диаграммы: * Не усложняй. Тебе хватит 3-4 таблиц (Пользователи, Курсы, Заявки).

Быстрая ER-диаграмма: Если на компах есть DBeaver, просто создай таблицы через SQL-скрипт init.sql, нажми на базу данных правой кнопкой мыши -> «ER-диаграмма». Программа нарисует её за тебя! Делаешь скриншот — баллы за проектирование в кармане.

Защита паролей (Хэширование): Не пиши свои алгоритмы. Используй встроенный make_password и check_password из django.contrib.auth.hashers. Это 2 строчки кода, которые дают максимальный балл за безопасность.

Токены и Сессии: Никаких JWT-библиотек. Возвращай обычный JSON с user_id и role, и сохраняй их на фронтенде в localStorage. Это полностью удовлетворяет требования ТЗ.

CORS: Решается добавлением 5 строк в обработчик OPTIONS прямо во views.py. Никаких сторонних библиотек django-cors-headers.

📂 Структура проекта
backend/ - серверная часть на Django (настройки БД, API, хэширование).

frontend/ - клиентская часть (верстка экранов регистрации, профиля, админки и скрипты).

database/ - файл init.sql для мгновенного создания таблиц и дефолтного админа.

docs/ - шпаргалки по офлайн-разработке и частые ошибки (например, проблемы с кодировкой в Windows).

🧠 Особенности проекта
Отказоустойчивость: Работает без интернета и npm.

Модульность: Каждый этап (Регистрация, Авторизация, Личный кабинет, Админка) расписан по шагам.

Фокус на критериях: Код написан так, чтобы "зацепить" самые дорогие пункты из таблицы оценки (например, подсистемы безопасности — 18 баллов).

Репозиторий создаётся в образовательных целях.
Не заучивай код наизусть! На экзамене от волнения ты забудешь любую строчку. Тренируй логику: как данные из HTML-формы превращаются в JSON, летят на сервер, обрабатываются Python-ом и ложатся в базу данных.
